# Deployment guide

This guide puts Smart Wall Paint Visualizer live on HTTPS with a custom domain, using the hosting recommended in the spec (§16):

| Part | Service | What runs there |
|------|---------|-----------------|
| Database | **MongoDB Atlas** | Users, colours, patterns, designs, activity |
| Images | **AWS S3** | Uploaded photos, renders, admin pattern tiles |
| API | **Render** (Docker) | `server/` — Express REST API |
| Web app | **Vercel** | `client/` — Angular app, also proxies `/api` to Render |
| CI/CD | **GitHub Actions** | lint → test → e2e → deploy on every push to `main` |

Plan for about an hour. You need accounts on each service and a domain name.

> The browser only ever talks to your web domain: Vercel forwards `/api/*` and `/static/*` to Render. That keeps everything same-origin (no CORS setup, simpler security headers).

---

## 1. MongoDB Atlas

1. Create a project and a cluster (the free **M0** tier is enough to start).
2. **Database Access** → add a database user with a long random password (role: *Read and write to any database*).
3. **Network Access** → allow `0.0.0.0/0` (Render's outbound IPs change), or use Atlas's Render integration if your plan supports private networking.
4. **Connect → Drivers** → copy the connection string and add a database name, e.g.
   `mongodb+srv://swpv:<password>@cluster0.xxxxx.mongodb.net/wall-paint-visualizer?retryWrites=true&w=majority`

Keep this as `MONGODB_URI`.

## 2. AWS S3

1. **Create bucket** (e.g. `swpv-prod-images`) in a region near your users. Leave **Block all public access** *on*.
2. **Bucket policy** — let anyone read only the `public/` prefix (admin-uploaded pattern tiles). User photos stay private and are only reachable through short-lived signed links:

   ```json
   {
     "Version": "2012-10-17",
     "Statement": [
       {
         "Sid": "PublicCatalogueAssets",
         "Effect": "Allow",
         "Principal": "*",
         "Action": "s3:GetObject",
         "Resource": "arn:aws:s3:::swpv-prod-images/public/*"
       }
     ]
   }
   ```

   For this policy to apply, turn off only the two "…public bucket **policies**" checkboxes under *Block public access* (keep the ACL ones on).

3. **CORS** — the studio draws photos onto a `<canvas>`, which needs CORS:

   ```json
   [
     {
       "AllowedOrigins": ["https://YOUR-DOMAIN"],
       "AllowedMethods": ["GET"],
       "AllowedHeaders": ["*"],
       "MaxAgeSeconds": 3600
     }
   ]
   ```

4. **IAM user** for the API with this policy (programmatic access → note the access key and secret):

   ```json
   {
     "Version": "2012-10-17",
     "Statement": [
       {
         "Effect": "Allow",
         "Action": ["s3:PutObject", "s3:GetObject", "s3:DeleteObject"],
         "Resource": "arn:aws:s3:::swpv-prod-images/*"
       }
     ]
   }
   ```

5. Optional: put CloudFront in front of the `public/` prefix and set `PUBLIC_ASSET_BASE_URL` to the CloudFront URL.

## 3. API on Render

1. Render dashboard → **New → Blueprint** → select this repository. Render reads `render.yaml` and creates the `swpv-api` web service (Docker, health check `/api/v1/health`).
2. Fill in the variables marked *sync: false*:

   | Variable | Value |
   |----------|-------|
   | `MONGODB_URI` | from step 1 |
   | `CLIENT_URL` | `https://YOUR-DOMAIN` (comma-separate several) |
   | `AWS_S3_BUCKET`, `AWS_REGION` | from step 2 |
   | `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` | the IAM user from step 2 |
   | `PUBLIC_ASSET_BASE_URL` | optional CDN URL |
   | `ADMIN_EMAIL`, `ADMIN_PASSWORD` | the first admin account (strong password) |

   `JWT_SECRET` and `FILE_URL_SECRET` are generated by Render.

3. Deploy, then open the service **Shell** and seed the catalogue and admin account once:

   ```bash
   npm run seed
   ```

4. Check `https://swpv-api.onrender.com/api/v1/health` returns `{"status":"ok","db":"connected"}`.
5. **Settings → Deploy Hook** → copy the URL (used by GitHub Actions below).

The API redirects plain HTTP to HTTPS, sends HSTS, and runs as a non-root user.

## 4. Web app on Vercel

1. In `client/vercel.json`, replace both `YOUR-API-HOST` with your Render host (e.g. `swpv-api.onrender.com`) and commit.
2. Vercel → **Add New → Project** → import the repository, set **Root Directory** to `client`. The build settings come from `vercel.json`.
3. Deploy, then **Settings → Domains** → add your domain and follow the DNS instructions. Vercel issues the HTTPS certificate automatically.
4. Make sure `CLIENT_URL` on Render matches this domain.

`vercel.json` also sets the security headers (CSP, HSTS, `X-Frame-Options`, etc.). If you serve images from a CDN, add its host to the CSP `img-src` and `connect-src`.

## 5. Continuous deployment (GitHub Actions)

`.github/workflows/ci.yml` runs on every push and pull request: API lint/tests/audit, app lint/tests/build/audit, then Playwright end-to-end tests against a fresh MongoDB. On pushes to `main` it then deploys.

Add these in **GitHub → Settings → Secrets and variables → Actions** (and create a `production` environment if you want manual approval):

| Secret | Where to get it |
|--------|-----------------|
| `RENDER_DEPLOY_HOOK_URL` | Render → service → Settings → Deploy Hook |
| `VERCEL_TOKEN` | Vercel → Account Settings → Tokens |
| `VERCEL_ORG_ID`, `VERCEL_PROJECT_ID` | run `npx vercel link` in `client/`, then read `client/.vercel/project.json` |

Until the secrets exist the deploy steps are skipped, so CI still passes.

## 6. Staging (optional)

Spec §16 asks for development, staging and production environments. Repeat steps 1–4 with separate resources (e.g. an Atlas database `wall-paint-visualizer-staging`, bucket `swpv-staging-images`, Render service `swpv-api-staging`, a Vercel preview domain) and their own secrets. Every Vercel pull-request preview can point at the staging API by using a second `vercel.json` rewrite target in a `staging` branch.

## 7. After going live

- Log in with the admin account, open **Admin → Settings** and review the upload limit and disclaimer text.
- Change the admin password from **Profile**.
- Watch **Admin → Dashboard** for uploads, saved designs, session time and satisfaction.
- Atlas: enable backups. S3: consider a lifecycle rule that removes incomplete multipart uploads.

## Environment variables (API)

| Variable | Required | Default | Purpose |
|----------|----------|---------|---------|
| `NODE_ENV` | yes | `development` | `production` enables HTTPS redirect and hides error details |
| `PORT` | no | `5050` | Port to listen on |
| `MONGODB_URI` | yes | — | MongoDB connection string |
| `JWT_SECRET` | yes | — | Signs login tokens |
| `JWT_EXPIRES_IN` | no | `1h` | Login session length |
| `CLIENT_URL` | yes | `http://localhost:4200` | Allowed browser origins (comma-separated) |
| `MAX_UPLOAD_MB` | no | `10` | Default upload limit (admins can change it in Settings) |
| `STORAGE_DRIVER` | no | `s3` if a bucket is set, else `local` | Where images are stored |
| `UPLOAD_DIR` | no | `server/uploads` | Local storage folder (development) |
| `FILE_URL_SECRET` | no | derived from `JWT_SECRET` | Signs private image links (local storage) |
| `FILE_URL_TTL_SECONDS` | no | `3600` | How long image links stay valid |
| `AWS_S3_BUCKET`, `AWS_REGION` | for S3 | — | Image bucket |
| `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` | for S3 | — | Credentials (omit on AWS with an instance role) |
| `PUBLIC_ASSET_BASE_URL` | no | bucket URL | Base URL for public pattern tiles |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD` | for seeding | — | First admin account created by `npm run seed` |
